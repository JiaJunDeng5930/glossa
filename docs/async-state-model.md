# Glossa 交互与异步状态模型（设计背景）

本文只保留 R38 设计中不能从单个函数直接看出的原因。它不是当前实现的唯一事实来源，也不列出完整的状态、接口或测试矩阵；当前行为以源代码、类型约束和针对真实代码的测试为准。跨模块取舍见 [ADR-0001](adr/0001-async-ownership-and-contracts.md)。

## 为什么采用状态 ownership

每份会改变用户可见结果、协议权限、外部副作用或持久化结果的可变状态，都有一个负责提交它的 owner。其他模块只能通过该 owner 的命令或存储边界提出变化。这样可以把浏览器回调、Promise 完成和端口消息归一为有序事件，避免同一事实由多个模块分别修补。

异步完成只在它仍属于当前输入、路由、生成代际或操作时提交。取消负责阻止后续 UI 提交和重试；已经发生的外部副作用则进入明确的成功或结果未知状态。UI 的可见状态从业务结果派生，不能让旧 Promise 覆盖较新的输入。

IndexedDB 的短事务承担需要原子转换的词汇和制卡历史更新。缓存清理与生成替换使用代际/epoch 约束，使过期读取或 AI 结果不能重新填充当前内存和持久缓存。后台异步工作共享 job，但页面会话仍能独立关闭和释放自己的订阅。

## 保持分离的身份

- content occurrence 表示页面中的一个源文位置，并携带该次请求的快照。
- `requestItemId` 只表示某次 AI frame 中的一项请求。它由 frame 分配，不能复用页面 token 或 occurrence ID。
- `GlossJob` 表示可共享的生成/cache 工作；subscriber 表示一个会话对一个 occurrence 的通知和写入行为。第一个 subscriber 不拥有 job 的生命周期。
- settings patch 表示用户实际修改的字段。页面保存 dirty leaves，worker 读取最新设置后合并 patch，避免陈旧完整表单覆盖未编辑字段。
- 一次点击对应一张 Anki 卡；`cardedWords` 记录单词级制卡事实，词汇学习状态和外部 note ID 保持不同含义。
- 连接测试、牌组目录和词汇视图使用发起控件自己的 operation state，晚到结果不能解锁或覆盖另一项操作。

这些身份边界是为了让每个 owner 能独立处理关闭、重试、缓存和外部提交，不是为了建立通用异步框架。

## 验证边界

类型和运行时校验负责拒绝不完整或不匹配的跨边界数据；行为测试负责证明真实协议、DOM、存储和外部调用在关键时序下的结果。文档记录原因，不替代实现、类型或测试，也不应维护一份手工状态清单。
